# MyGO!!!!! × Ave Mujica 资料库

一个围绕《BanG Dream! It's MyGO!!!!!》与《BanG Dream! Ave Mujica》整理的中文资料库，收录动画剧情、角色资料、官方访谈、漫画与游戏内容、剧场版资料、社区解析及角色关系梳理。

仓库地址：https://github.com/xoqnapgf-dot/bangdream

在线网站：https://xoqnapgf-dot.github.io/bangdream/

网站采用文件浏览器形式展示资料：桌面端左侧为目录树，移动端可从菜单打开目录；点击文件即可阅读正文。

## 二、网站功能

- 文件夹树导航，可展开或收起目录
- 角色目录内优先显示 `人设汇总_*.md`
- Markdown 与纯文本阅读
- MyGO 13 集台词底稿按说话人、台词、动作提示和独白排版，睦／祥子视角长文按段落排版
- 标题、引用、表格、列表、代码块与普通图片渲染
- Bilibili 视频站内播放
- 响应式图片画廊；剧情配图会分散插入正文，不堆在文件开头
- 剧情补全采用官方资料、逐帧字幕和多个独立社区来源交叉核验，剧情事实、制作资料与社区推测分别归档
- 文件名与标题搜索
- 正文大纲与滚动定位
- 文件交叉引用跳转
- 深色、浅色主题切换
- 桌面与移动端响应式布局
- 目录状态标记：全锁（`01_MyGO动画`、`02_AveMujica动画`、`05_官方访谈与设定`、`06_社区解析_推测`）表示内容已基本确定、不再新增；半锁（`03_剧场版`、`04_漫画游戏`、`07_CP线梳理`）表示后续仍会补充新内容。名单配置在 `assets/app.js` 顶部的 `PROTECTED_DIRS`（原始资料）、`CURATED_PROTECTED_DIRS`（社区解析）与 `PARTIAL_PROTECTED_DIRS`（半锁）三处，改目录状态只需增删路径；图标仅作提示，不影响点击和阅读
- Hash 路由，可分享具体文件地址
- 浏览器后退或前进时恢复离开前的阅读位置
- 完整仓库可直接双击 `index.html` 离线阅读
- 窄屏右下角按需出现浮动返回按钮（详见「四、7 页内跳转与返回按钮」）
- 长篇转载可收进折叠区块，默认收起（详见「四、6 可折叠区块语法」）

项目为纯静态网站，使用原生 HTML、CSS 和 JavaScript，不依赖前端框架，也不需要打包构建。

## 三、阅读注意事项

### 1. 剧透

资料库包含完整剧情、角色经历、剧场版新增段落、结尾及人物关系分析。阅读动画、剧场版和角色文件时可能遇到大量剧透。

### 2. 官方内容与社区观点

官方剧情、设定、访谈和商品信息，与社区解析、考据、推测及 CP 向内容属于不同类型。社区观点不代表 Bushiroad、BanG Dream! Project、动画制作团队或出演者的官方结论。

补写剧情时会参考粉丝整理的逐话记录与解析，把正文漏掉的场面和对白补回资料库。归属按三层分开写：剧情描述与按场景记录的原句进剧情总纲；制作方式、主创发言等进 `05_官方访谈与设定` 并注明出处；粉丝推论进 `06_社区解析_推测` 并标注【推测】和来源。台词优先用官方切片、逐帧字幕或独立记录交叉核对；整场连续记录可在校正明显听写错误后按上下文收录，但必须保留原文链接，不能把记录者的感想混入剧情。

### 3. 原始底稿

动画台词、剧本、访谈原文及公式书整理属于资料底稿。维护时应尽量保持原貌；目录排序、显示名称和阅读体验优先通过前端处理。

### 4. 图片与视频

剧场版页面使用电影官网、BanG Dream! 官方网站及官方 Bilibili 账号的远程资源，仓库不保存这些图片和视频的副本。

远程资源可能因官方改版、地址调整、地区限制或平台播放策略而暂时无法加载。图片或视频失效时，应优先更新为新的官方地址，不要改用来源不明的转载资源。

### 5. 来源链接

普通来源以可点击链接集中列在相应文件末尾。引用资料时，建议继续查看原始页面，尤其是访谈、影院档期、商品规格和社区分析。

### 6. 版权

本项目为非官方资料整理。作品名称、角色、图片、视频、音乐及相关版权归 BanG Dream! Project、Bushiroad 及各权利方所有。

## 四、维护注意事项

### 1. 重新生成目录清单

增删或修改 `资料库/` 内文件后，运行：

```bash
python3 tools/build_manifest.py
```

`assets/manifest.json`、`assets/offline-data.js` 与 `资料库/项目文件大纲.txt` 由脚本生成，不应手工修改。脚本也会更新 `index.html` 中的静态资源版本号，避免浏览器继续使用旧缓存。页面显示的清单生成时间固定使用北京时间（UTC+8），不跟随运行脚本的服务器时区。

### 2. 本地阅读与预览

下载完整仓库并保持目录结构后，可直接双击 `index.html`。页面通过 `assets/offline-data.js` 读取目录、正文、视频元数据与剧集数据，不依赖本地服务器。

如需用 HTTP 环境检查，也可运行：

```bash
python3 -m http.server 8080 --bind 0.0.0.0
```

然后打开 `http://localhost:8080/`。

### 3. Bilibili 视频语法

```markdown
@[bilibili](BV1xxxxxxxxx "视频标题")
```

渲染器只接受 BV 号，不要直接向资料正文加入任意 iframe。

页面上先渲染一块封面占位（封面取自 `video-meta.json` 的 `cover`），读者点击后才插入 Bilibili 官方站外播放器并自动开始播放。这样做有两个原因：站外播放器自带的封面时有时无，自己控制才能保证每个视频都有画面；一页有多个视频时也不必一次性加载多个 iframe。封面下方始终有「在 B 站打开」的跳转链接。

新增视频时必须同时在 `assets/video-meta.json` 里补一条记录，四个字段缺一不可：

```json
"BV1xxxxxxxxx": {
  "aid": 447482327,
  "cid": 1238132939,
  "cover": "https://archive.biliimg.com/bfs/archive/<hash>.jpg",
  "title": "视频标题"
}
```

只写 BV 号而缺 `aid` / `cid` 时，站外播放器会解析失败——页面上表现为播放区域空白、封面也不出来，只剩下方的「在 B 站打开」链接可用。这几个字段取自 `https://api.bilibili.com/x/web-interface/view?bvid=BV号` 返回的 `data.aid`、`data.cid`、`data.pic`（`pic` 换成 `archive.biliimg.com` 域名以与既有记录一致）。该文件为手工维护，`tools/build_manifest.py` 只读取、不会自动抓取。

### 4. 剧本与视角叙述的排版（.txt）

`.txt` 不走 Markdown 渲染，页面按 `assets/episode-meta.json` 里是否有对应条目决定怎么排：

- 有条目且没写 `layout`：按**剧本**排。整行按「姓名：台词」拆成说话人与台词两栏；`（……）`开头的行是动作与画面提示；`***……***` 是整段说明；`*` 开头是写在笔记本上的字。原文里的空行保留成段落间距。
  - 底稿用 `#` 标记心里话，共三种写法：单独成行的 `#独白`、`姓名：#独白`、`姓名：（动作）#独白`。渲染时去掉 `#`，台词转成灰调斜体。判定时 `#` 必须紧跟在行首、冒号或右括号之后——第 6 集「爱音：F#……」里的 `F#` 是吉他和弦，照搬规则会被误删。
  - 讲解这套标记本身的说明行（第 3 集与第 10 集各一处），其中的 `#` 是字面引用，保留不动。
- 条目里写了 `"layout": "prose"`：按**长文**排，短行（16 字以内且不含句读）当阶段小标题，其余各自成段。
- 没有条目：保持原来的等宽纯文本块（`资料库/项目文件大纲.txt` 属于这一类）。

条目同时提供文件顶部的资料卡，字段都是可选的：

```json
"00_剧情区/01_MyGO动画/03_CRYCHIC.txt": {
  "ep": 3,
  "titleJa": "CRYCHIC",
  "synopsis": "一句话梗概",
  "quote": "官方挑出的代表台词",
  "images": ["https://……png"],
  "staff": { "脚本": "…", "分镜": "…", "演出": "…" },
  "links": [{ "text": "互见文件", "href": "同目录文件.md" }],
  "source": "https://anime.bang-dream.com/mygo/story/"
}
```

`images` 也可以写成 `{"src": "…", "caption": "…"}` 来带图注。**第一张作文件顶部的封面，其余会自动摊到正文里**——按张数均分全文，再就近吸附到最近的场景切换处；吸附距离超过全文 8% 就按均分位置直接插，避免几张图挤在开头或全挤到结尾。`links` 里的相对路径会自动解析成站内跳转，指不到文件时显示为失效引用。MyGO 13 集的场面图、日文原标题、梗概、代表台词与制作名单均取自[官方网站 Story 页](https://anime.bang-dream.com/mygo/story/)。

改这个文件后要重跑 `tools/build_manifest.py`，否则本地双击打开时读到的还是旧数据。

### 5. 图片画廊语法

```markdown
@[gallery]
![图片一](https://example.com/1.jpg "图片一说明")
![图片二](https://example.com/2.jpg "图片二说明")
@[/gallery]
```

画廊只接受 HTTPS 图片地址。

**配图必须先确认画面里是谁**，不能凭文件名或话数推测——动画各话的场面图光看地址分辨不出人物，照猜必错。可用的核实办法是把候选图取到本地逐张看过再决定。

配图来源按以下优先级：

1. 官方网站的主视觉、角色立绘、应援插画（`anime.bang-dream.com`、`mygo-movie`、`avemujica-movie`）——身份明确，最稳妥。
2. 同人素材整理库 [Furinaaa-Cancan/mygo-mujica-archive](https://github.com/Furinaaa-Cancan/mygo-mujica-archive)——收录了按内容命名的动画场面截图，适合给具体桥段配图。引用时用 jsDelivr 并固定到某个 commit，形如 `https://cdn.jsdelivr.net/gh/<owner>/<repo>@<commit>/assets/...`；该库为 CC0 / 非商业同人授权，使用时需在文件的来源索引里注明出处。
3. B 站图床（`archive.biliimg.com`）——国内访问最稳，视频封面都走这里。

所有正文图片都会带 `referrerpolicy="no-referrer"`（部分图床按 Referer 防盗链）。图片加载失败时不会留空白，而是显示「图注 +（图片未能载入，点击打开原图）」的可点击占位，因此即使某个域名在部分地区访问不了，读者仍能知道这里本该是什么图。

资料库的配图惯例：角色人设汇总配该角色的官方立绘；CP 单篇配双方立绘；已逐张看过、确认画面人物无误的桥段改用真实场景截图。剧情类文件按小节配图。

图注里的话数也要核对过再写。官方场面图的文件名和上传日期能对上话数，可以直接用；从素材库取的截图则要先按截图上的字幕到逐帧字幕数据里检索时间码，确认它属于哪一话（做法见下一节）。只有在既看过画面、又查过话数之后，图注才可以同时写出人物和话数；两样里缺哪一样，就只写能确定的那一样。

### 6. 可折叠区块语法

```markdown
@[details](展开原文)
这里是默认收起的内容，支持完整 Markdown，可以嵌套。
@[/details]
```

用于「概述在外、长篇原文收起」的场合，例如整段转载的外部讨论。默认收起，点击标题展开。转载他人长文时的推荐写法是：先用自己的话概述几条主要观点，给出原帖链接，再把原文放进折叠块——既不丢原文，也不会让转载内容淹没正文。

### 7. 页内跳转与返回按钮

正文里出现跳转时，窄屏（宽度 1180 像素以下，右侧大纲已隐藏）右下角会按需浮出返回按钮；没有跳转就不出现，不占版面。宽屏用右侧「本文大纲」即可，因此不显示。

右下角最多出现两个按钮：

| 按钮 | 出现条件 | 作用 |
| --- | --- | --- |
| 目录 | 文中有名为「目录」的标题 | 回到该文内目录 |
| 返回 / 上一页 | 刚发生过本页跳转或跨文件跳转 | 回到跳转前的滚动位置，或回到来源文件 |

跳转的写法与处理：

- 本页跳转写 `[章节名](#章节名)`，锚点按标题文字匹配。跳转目标标题会自动获得行内「返回目录」小按钮。
- 跨文件跳转写 `[说明](../目录/文件.md)`，或直接在正文写出 `灯x祥子.md` 这类文件名，交叉引用会自动转成站内链接。
- 从侧栏、搜索或浏览器后退进入的页面不算跳转，返回按钮不出现，也不会留下上一页的残留记录。

相关逻辑集中在 `assets/app.js` 的「右下角按需返回」一节，配合 `resolveHeadingLinks` 与 `resolveContentLinks`。新增或改写资料时只要使用上述两种写法，返回按钮会自动跟上，不需要在正文里加任何额外标记；如果今后引入其他形式的跳转，需要同步确认右下角返回按钮仍然可用。

### 8. 台词与剧情核对用的外部数据

整理剧情、引用台词时用到过以下公开数据，均只作核对依据，不直接照抄进资料库：

| 来源 | 内容 | 用途与局限 |
| --- | --- | --- |
| [日文五十音练习所 · Ave Mujica](https://www.japanese50sounds.com/anime/ave-mujica/) | 19 条经典台词，带说话人、话数与日文原文 | 有说话人和话数，可直接对位；条目数有限 |
| [phillychi3/MyGo-Meme](https://github.com/phillychi3/MyGo-Meme) | 逐帧 OCR 字幕，MyGO 全 13 话、Ave Mujica 第 1–9 话共 20,777 条，带时间戳 | 能把任一句定位到「第几话第几分秒」，也是划分小节话数、核对图注的依据；但混有 OP/ED 歌词与制作名单、存在识别错字，只可定点检索、不可通读取材，且缺 Ave Mujica 第 10–13 话 |
| [Furinaaa-Cancan/mygo-mujica-archive](https://github.com/Furinaaa-Cancan/mygo-mujica-archive) | 2,645 张按内容命名的截图 | 配图来源；文件名是孤立单句、没有说话人也没有上下文，**不可当台词原文使用** |
| [辻（カモネギ）· Ave Mujica 第 1–13 话记录](https://note.com/srx40090) | 12 篇逐话文章，含场景顺序与较长对白记录 | 用于寻找总纲可能遗漏的场景、核对第 10–13 话（OCR 未覆盖）的叙事顺序；文章混有个人感想、解读、预测与 AI 查询结果，只有能被画面、官网或另一份独立记录确认的具体信息可以进入剧情正文。12 篇直达链接统一保存在 Ave Mujica 剧情总纲文末 |

引用台词的规矩：优先由官方切片、逐帧 OCR 或两个独立记录交叉确认。对于按镜头顺序保存整场对话的详细逐话记录，可在排除明显听写错误、确认上下场景连续后，把原句放回对应剧情现场并在文末保留文章直达链接；不要再另建脱离上下文的「名台词摘录」表。作者的情绪、评价、CP 评论、因果解读、巡礼推测和后续预测不进入剧情区。

用逐帧字幕定位话数时有两个坑，都踩过：

- **每话开头约一分半是「前情提要」，会原样重复上一话的台词。** 同一句检索出两个时间码时，靠后的那一次（位于上一话末尾）才是它真正出现的位置，开头那一次是回顾。按开头那次判断，整段剧情就会被归错话数。
- **剧情小节的话数不能按主题推断。** 一个主题常常横跨两话，而一话里也常有两条并行剪辑的线。给剧情文件划分小节、写图注话数之前，先挑该节里几句有代表性的台词去检索时间码，以时间码为准。

这两点合起来会造成系统性偏差：Ave Mujica 剧情总纲曾把第 7 至 10 话的内容整体错标了一话，直到逐句检索时间码才发现。改动剧情类文件的结构时值得先跑一遍这个检查。

### 9. 提交前检查

```bash
node --check assets/app.js
python3 tools/build_manifest.py
git diff --check
```

还应分别通过本地双击和 HTTP 环境检查：

- 首页和目录是否能够打开
- 修改后的文件是否能正常读取
- 图片画廊在桌面与手机宽度下是否正常
- 改过 `assets/episode-meta.json` 后是否重跑了 `tools/build_manifest.py`：漏跑时网页版正常、本地双击打开却读不到新的资料卡
- 视频封面是否显示、点击后是否真的开始播放：新增视频要确认 `assets/video-meta.json` 里 aid / cid / cover / title 齐全，缺 cover 只剩底板，缺 aid 或 cid 则点开后是一块空白
- 折叠区块是否默认收起、点击能展开
- 配图里的人物是否与正文小节对得上（必须真的看过图，不能凭文件名推测）
- 普通来源链接是否可点击
- 新增跳转的文件：窄屏下点跳转后，右下角「返回 / 上一页」是否出现并能回到原处
- 新增或调整目录锁状态后：侧栏该目录的小锁 / 半锁图标是否正确

### 10. GitHub Pages 与预览链接

GitHub Pages 从 `main` 分支根目录部署，合并后网站才会更新。

包含 commit ID 的 RawGitHack 链接是固定版本链接。它不会随着分支继续更新；查看新改动时需要打开新 commit 对应的预览地址。

预览链接的使用规则：

- 每次完成并推送修改后，提供对应最新 commit 的 RawGitHack 固定预览链接，不再沿用旧 commit 的地址。
- RawGitHack 仅用于审阅。站内导航、资源引用和离线阅读都不得依赖它：`index.html`、`assets/` 与 `资料库/` 之间一律使用仓库内的相对路径，保证双击本地文件和 GitHub Pages 两种方式都能独立运行。

## 六、更新原则

- 优先采用官网、官方公告、正式商品页和可访问的原始来源。
- 剧情事实、官方设定和社区观点保持清楚的内容归属。
- 不把推测写成官方剧情。
- 相似内容不等于重复内容，删改前应确认是否存在信息差异。
- 概括用于帮助阅读，不代替需要保留的原始文本。
- 图片和视频只选与正文直接相关的官方素材，避免堆砌。
- 页面正文面向读者展示内容，不写核验过程、内部修改记录或反复自我说明。
