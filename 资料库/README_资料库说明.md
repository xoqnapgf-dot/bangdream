## 四、核心整理规则（★务必遵守）

### 1. 先区分「正式文件」与「采集素材」
- **正式文件** = 各板块已存在的**汇总/人设/确证/CP 文件**（如 `MyGO_分析推测汇总.md`、`AveMujica_分析推测汇总.md`、`人设汇总_XXX.md`、`MyGO_确证内容汇总.md`）。这是资料库主体。
- **采集素材** = 从贴吧 / 知乎 / 小红书 / B站 / NGA 等平台复制下来的**原始内容**，是待整合的原料，**不是正式文件**。

### 2. 采集素材处理流程：属性分流 → 并入已有正式文件 → 删原素材
采集的内容按属性归类落位：

- **强人设、弱剧情**（讲性格、内心、人物关系、病理分析）→ 并入**对应角色的人设汇总**，人设文件放**全文**。
- **强剧情、弱人设**（讲剧情走向、叙事结构、事件）→ 并入**剧情区对应文件**：MyGO 内容进 `MyGO_分析推测汇总.md`，AveMujica 内容进 `AveMujica_分析推测汇总.md`。**跨团内容可在两边剧情区都放全文**。
- 人设内的解析部分默认**简略**，重力按上述属性落位，不铺开、不打补丁。

整合完成后，**删除采集原文件**（不保留任何独立采集文件）。

### 3. 禁忌（以下行为一律禁止）
- ❌ **不新建文件**到正式区域。所有采集内容必须并入**已有**正式文件，不许新开「社区解析_XX」「官方访谈_XX」「澄清_XX」等独立文件。
- ❌ **不打「可信度 / 分类」标签**（如 ✅与官方一致、⚠️个人推测、🔗可对照资料、主题归组等）。社区解析本来就没有「确证」，确证只存在于官方访谈与设定。解析内容**直接整段并入**即可，不贴可信度徽章、不做多余归类标记。
- ❌ **单个文件内部不重复、不复读**。同一观点只在文件内出现一次。人设区与剧情区**可以跨区**重复（强剧情可两边都放），但**单文件内部禁止复读**。

### 4. 出处统一末尾陈列
凡是带**具体作者 / 账号名 + 时间（有 URL 连同 URL）** 的考据出处，从正文剥离，统一**集中到每份文件最末尾**集体陈列：

- 每个**角色人设文件**末尾
- **MyGO 剧情解析**末尾
- **AveMujica 剧情解析**末尾

正文只保留观点内容，来源集中在文件末尾，不穿插在正文中。

## 五、官方访谈 / 公式书
- **公式书（FOOTPRINTS）**：别管、不动，原样保留。
- **官方访谈**：作为原始材料，**源文件放 `05_官方访谈与设定` 保留不删**；只提取其中的内容进人设或剧情区。
- **确证内容汇总**（MyGO / AveMujica）：官方一手来源，**保留不删**。

## 六、原样保留原则
- 动画台词、剧本等**剧情原文为原始底稿，不删不改**。
- 社区解析内容保留采集来源，可溯源验证。
## 七、内容处理守则（★补充，与第四部分同样强制）

- **相似 ≠ 重复**：内容相近但并非完全一致时，不得当作"重复"删掉；要保留差异，保留完整观点，不因"看起来像"就合并或丢弃。
- **概括 ≠ 原文**：概括/提炼**不能替代原始文本**；原文必须保留，概括只作阅读辅助，绝不能作为删减原文的理由。
- **推测 ≠ 事实**：社区解析 / 推测**不得改写成确凿事实的表述**；写入时须保持其"社区观点 / 推测"性质，标注非官方，与官方设定区分。
- **需要时可搜索确认、对比**：遇到不确定、需多方交叉验证的信息，用联网搜索确认、比对，**可多轮搜索**；不凭记忆臆断、不编造。
- **请求使用平衡**：少调用、少浪费请求；但**不要为了"省"而故意少用，也不要乱刷**——该用的用、该省则省，不走极端。
- **前台执行**：**不在后台跑子程序 / 子 session**，所有整合、写入、确认操作都在 coze 前台（当前会话）直接完成。
